# Experiment design

## Pick the method by what you need to learn
| Unknown | Cheapest decisive methods |
|---|---|
| Is the problem real and painful? | 5–10 Mom Test interviews; search for existing workarounds and spend |
| Will they want this solution? | Concierge / Wizard-of-Oz; clickable mockup with a real task |
| Will they pay? | Fake door with price; preorder or deposit; manual invoice |
| Can we reach them? | Small channel tests (outreach, communities, creators, small ad budget) to a landing page |
| Can we build it? | Spike or prototype on the hardest part only; eval set for AI quality |
| Do they stay? | Concierge for 2–4 weeks; measure repeat usage |

## Rules
- One primary metric. Secondary metrics can explain, never decide.
- Pass and kill thresholds written now. A middle zone means "iterate once", not "keep going forever".
- Thresholds should be set where a result would actually change what you do. If no plausible result would change the decision, don't run the test.
- Sample size honest for the method: 5–10 for interviews/qualitative; for conversion tests, say what difference the sample can and cannot detect.
- Cost cap in money and hours. Deadline ≤ 2 weeks unless there's a reason.
- Name what could make the result misleading (biased sample, friends and family, novelty effect) and how you limit it.

## Output
A filled card in the format from `venture-state`, ready to paste into `ledgers/experiments.md`.
